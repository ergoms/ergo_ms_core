# Самостоятельная поставка аналитических операций: источники D2

Срез 25.10.2026. Продолжение [D1](analytics-operations.md). Этап D закрыт в проверенном
контуре PostgreSQL/CPU: из локального остатка BI выделены зависимости запуска
датасетов. Новый установщик, зависимости и изменения ядра не потребовались.
Прочие изменения стабилизации в серию не входят.

## Поведение

`DatasetQueryExecutor` выбирает подключение таблиц датасета и не подменяет
отказавшую внешнюю БД основной БД. Основная PostgreSQL-БД используется только
для подготовленных файловых `VALUES`. Пустой/непривязанный источник, JOIN разных
подключений и таблица модуля без подготовленного файла отклоняются.
Файлы, предоставленные модулем через существующий bridge, продолжают читать
через media_api. Чтение общего справочника через bridge не заменяет HTTP ACL.

Для внешнего PostgreSQL URL собирается через SQLAlchemy `URL.create`:
специальные символы пароля/имени не меняют адрес подключения. Схема таблицы
читается inspector, без подстановки её имени в сырой SQL. SQLAlchemy engine
исполнителя освобождается при успехе и ошибке. Существующий MSSQL-драйвер
в этой серии не переключается; его альтернативная локальная правка сохранена.

Общий builder применяет JOIN, переименования через логические имена, типы,
параметры и зависимости формул. Циклические формулы отклоняются. Поиск и его
COUNT выполняются по преобразованным значениям; LIMIT не обрезает файл до поиска.
Ячейки файлов передаются параметрами, включая даты, NULL, кавычки, проценты,
двоеточия и строки, похожие на SQL placeholders. Пустая таблица сохраняет колонки.
EDA/новые операции семплируют результат после преобразований.

Предпросмотр, фоновый предпросмотр, SQL-графики и профиль используют тот же
исполнитель. График не вычисляет формулу повторно поверх готового поля.
Быстрые файловые пути ограничены совместимыми случаями; числовые значения
нормализуются согласно типу поля, суммы сохраняют Decimal-точность.
Независимый шаринг графиков не получил дополнительного требования доступа к датасету.

Существующий `PATCH /api/bi_analysis/bi_datasets/<UUID>/` принимает выбранное
`connection` как UUID и `file_source` как прежний файловый id, вместе с `table_ref`.
Перед сменой проверяются права подключения/таблицы/файла. Смена главного источника,
сброс прежних JOIN и изменение полей выполняются одной транзакцией; ошибка не
оставляет переименованный датасет или частичные привязки. Добавление файловых
связей также проверяет доступ; чужие метаданные таблиц скрыты. Маршруты сохраняются.

Старые EdaReport/AnalysisReport остаются в исходных таблицах. Результаты, время,
инициатор и прочие поля не пересчитываются; D1 продолжает читать их через архив.
Миграции схемы D2 не добавляет.

## Проверки

Новые регрессии запущены до исправления исполнителя: 16 тестов, два падения
и одна ошибка подтвердили обращение к основной БД/отсутствие ранней валидации.
После исправления они прошли. Окончательный состав содержит 26 проверок источников.

Чистая копия собрана `git archive` из HEAD обёртки, core/api, core/client и BI.
Рабочая копия поверх неё не накладывается; все 23 выбранных файла сверены с Git
blobs и проверены AST. CRLF, применяемый архиватором по атрибутам репозитория,
учтён при побайтовой сверке. Используется существующий SDK, без установки пакетов.

- На HEAD: 26 регрессий источников OK, полный BI — 188 тестов OK, четыре пропуска.
- В полной рабочей копии: 239 тестов BI OK, пять пропусков; последняя проверка
  добавления чужого файла в оба endpoint дополнительно входит в 26 тестов HEAD.
- На предварительном составе и повторно на HEAD реальный Windows solo-worker выполнил
  EDA, boxplot, linear, ARIMA и SARIMA с частным SQLite-брокером, без eager.
  Прочитана внешняя PostgreSQL-БД вместо одноимённой таблицы основной QA-БД.
  Каталог/запуск/статус прошли через HTTP bridge. Повторные запросы не создали
  дубликатов; чужой субъект получил 404, снимки проверены, старые отчёты неизменны.
- `core-rules-check`: те же пять прежних ошибок размера документов CRM,
  новых ошибок относительно D1 нет.

Миграции всех включённых приложений ядра и BI прошли на новой собственной БД;
повтор вернул `No migrations to apply`. Приёмочная копия HEAD соответствует
`modules/bi_analysis=1677a0719e4f016b9020af9dbe52ae7a108e1ccc` и
`core/api=0b149a52664a67049ba30d0eb8860bc0ad6df412`. Никаких исходников из рабочей
копии поверх неё не добавлялось. Оба solo-worker завершились с кодом 0;
собственные БД обоих сквозных профилей удалены, QA PostgreSQL остановлен.

## Границы

Серия не включает оставшиеся дашборды, UUID-миграции, CRUD-аудит, прежние private
task API, клиент, зависимости или альтернативный MSSQL-драйвер. В четырёх смешанных
файлах выбраны только нужные фрагменты; полная рабочая копия этих файлов сохранена
побайтово. Прочие локальные правки сверяются с исходным снимком 22 репозиториев.
Параллельные изменения LMS отмечены отдельно и не включены в коммиты.

MSSQL/ClickHouse, реальный remote media_api, Linux Celery, Redis/RabbitMQ,
разные физические хосты, чистая установка
SDK, весь клиент и нагрузочная матрица этой поставкой не подтверждены.
Наличие кода провайдера не означает интеграционную проверку. Прежние исправления
private task API и дашбордов остаются отдельным локальным остатком; завершение D
не объявляет их самостоятельной поставкой. SSH, production, push и обновление
gitlinks не выполнялись.
