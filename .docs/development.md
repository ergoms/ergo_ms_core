# Запуск системы разработки

В режиме разработки ERGO MS — это несколько процессов, которые можно поднимать по отдельности или одним жестом из IDE. Они не требуют прав администратора (в отличие от установки системных служб на Linux или Windows).

## Из чего состоит стенд

**API** (Django) по умолчанию слушает порт **8000**. Запуск: `ergoms dev`. Команда перед стартом прогревает кэши обнаруженных приложений и модулей — первый запуск после клонирования поэтому может занять чуть больше времени, зато последующие будут быстрее.

**Клиент** (Vue + Vite) — порт **8001**, команда `ergoms start-client`. Это отдельный dev-сервер с горячей перезагрузкой компонентов.

**Media API** — порт **8003**, команда `ergoms start-media`. Нужен, если в сценарии есть загрузка или скачивание файлов через подписанные URL.

**Celery worker** (`ergoms start-worker`) выполняет фоновые задачи из очередей. **Celery beat** (`ergoms start-beat`) — планировщик по расписанию. Конфигурация worker'ов — в `celery_workers.yaml`.

Удобный компромисс: **`ergoms start-all`** поднимает API, worker и beat в одном терминале; клиент при этом всё равно лучше запустить отдельно — `ergoms start-client` — или воспользоваться задачей сборки в IDE.

Самый быстрый способ поднять всё разом в Cursor или VS Code — **`Ctrl+Shift+B`**: там настроен запуск полного набора сервисов для разработки.

## Куда смотреть логи

Все журналы складываются в каталог **`logs/`** в корне проекта. Там лежат общие файлы вроде `celery.log`, `celery_worker.log`, `media_api.log`, а также подпапки **`modules/<имя>/`** с логами конкретных модулей. Если что-то «молча» падает в фоне, имеет смысл открыть соответствующий лог, а не только вывод терминала.

Если API и клиент установлены как системные службы (production-подобный сценарий), смотреть их можно через `ergoms logs <имя-службы>` — подробнее в [deployment.md](deployment.md).

## Повседневные команды

Полный справочник — в [cli.md](cli.md). Из того, что понадобится чаще всего:

```cmd
ergoms migrate-all
ergoms api createsuperuser
ergoms warmup-caches
```

Первая создаёт и накатывает миграции, вторая — учётную запись администратора для входа в систему, третья — принудительно обновляет кэши, если после смены модулей API ведёт себя странно.

## Адреса в браузере

После запуска:

- интерфейс: http://localhost:8001  
- API (Swagger, health): http://localhost:8000  
- media_api: http://localhost:8003  

Порты можно изменить в `.env`, если 8000–8003 заняты другими программами.
