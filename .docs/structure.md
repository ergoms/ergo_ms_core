# Структура проекта

## Конфигурационные файлы

- `.env.example` / `.env` — базовая спецификация переменных окружения. Глобальный `.env` определяет поведение ядра, тогда как модульные `.env` в `modules/*` и `core/*` расширяют конфигурацию локальными параметрами (путь к пакетам, GPU-настройки, ключи интеграций).
- `databases.yaml.example` / `databases.yaml` — декларативное описание подключений к основным и вспомогательным БД. Поддерживаются PostgreSQL, MySQL и SQLite; строки со специальными символами заключаются в двойные кавычки.
- `menu-order-config.json.example` / `menu-order-config.json` — схема сортировки пунктов меню клиентского приложения. При отсутствии пользовательского файла задействуется дефолтный конфиг ядра.
- `.cursor/mcp.json` — реестр MCP-серверов Cursor: `ergo-api` (запросы к API), `ergo-database-postgres`, `ergo-filesystem`, `ergo_ollama`.
- `.cursor/rules/*.mdc` — правила разработки для AI-ассистента Cursor, определяющие стандарты кодирования, архитектурные паттерны и конвенции проекта. Применяются автоматически при каждом взаимодействии с ассистентом.
- `.cursorignore` — фильтр индексации Cursor; исключает крупные бинарные артефакты (изображения, базы данных и т.д.) для ускорения поиска.
- `.vscode/settings.json` — единые правила форматирования, линтинга и отображения для VS Code/Cursor.
- `.vscode/tasks.json` — сценарии автоматизации для установки зависимостей, запуска сервисов и работы с модулями на обеих платформах.
- `.vscode/extensions.json` — рекомендуемый набор расширений для синхронизации команды.
- `core/deployment/commands.conf` — команды CLI для задач `tasks.json` и утилиты `ergoms`.
- `core/deployment/logic.md` — правила и детали работы deployment-команд.
- `celery_workers.yaml` — конфигурация воркеров Celery (очереди, процессы).
- `modules/*/ergoms.conf` — модульные команды, регистрируемые с префиксом имени модуля.
- `modules/*/client/js/menu-config.json` — локальные схемы меню модулей.
- `pyrightconfig.json` — границы статического анализа Python и дополнительные пути импорта для форков Django/DRF.
- Прочие справочные файлы (`README.md`, `logic.md` в подпапках) документируют архитектурные решения и не содержат исполняемой логики.
