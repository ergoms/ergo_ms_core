## Манифест версии 1

```yaml
schema_version: 1
module: my_module
tools:
  - name: libreoffice
    required: true
  - name: tesseract
    required: false
models:
  - provider: huggingface
    repo: org/model
    required: false
  - provider: ollama
    env: MY_MODULE_MODEL
    default: embeddinggemma
    kind: embedding
    required: true
python:
  groups: []
```

`module` можно опустить; указанное имя должно совпадать с каталогом.
Строка в `tools` равнозначна `{name: ..., required: true}`. Инструмент
должен существовать в общем реестре. Достаточно одного потребителя
с `required: true`, чтобы инструмент стал обязательным. Повторные инструменты,
неизвестные поля, неверные типы, повторные ключи YAML и другая версия — ошибки.

Для моделей поддерживаются `huggingface` с `repo` или `env`/`default`
и `ollama` с `name` или `env`/`default`. Поле `kind` относится к Ollama.
Загрузку выполняют прежние механизмы Hugging Face и модуля-провайдера Ollama.
Общий индекс моделей, проверенные пути runtime и политика скачивания реализованы
в этапе B: [runtime-models.md](runtime-models.md).

`python.groups` ссылается только на существующие группы корневого Poetry.
Неизвестная группа останавливает установку. `python-install` передаёт группы
в прежний `poetry install --with ...`; зависимости и lock не генерируются.
При bootstrap без PyYAML манифест читается после установки основных
Python-зависимостей; при необходимости тот же Poetry доустанавливает группы.
На повторном запуске действует прежний fingerprint. Новые математические
группы относятся к этапу C.

Переменная процесса имеет приоритет над объединёнными `.env`; при пустом
значении применяется `default`. Загрузчик останавливает свой шаг, если
обязательная модель не разрешилась. Необязательная пустая модель пропускается
с диагностикой. `repo` и совместимый `name` не могут обозначать разные
снимки в одной записи.

Discovery использует `ModuleCatalog`: `DISABLED_MODULES` и незаполненные
каталоги подмодулей исключаются. Незагруженный модуль следует предварительно
инвентаризировать по закреплённой ревизии.

## Lifecycle и совместимость

```text
ergoms runtime-check
ergoms runtime-check --json
ergoms runtime-install-tools
ergoms runtime-install-tools --include-optional
ergoms package-status libreoffice
ergoms package-install libreoffice --force --refresh
```

`runtime-check` проверяет ссылки, группы и согласованность модельных
объявлений без установки. `runtime-install-tools` ставит обязательные инструменты;
`--include-optional` явно включает остальные. Поддержка ОС проверяется для
всех выбранных инструментов до начала установки.

В `setup-full` шаг `runtime_requirements` стоит после `python_and_npm`, до
Hugging Face и модульных задач. Bootstrap не импортирует PyYAML: вызывается
отдельный процесс venv. Docker использует прежний `run_api_oneoff`.
Ошибка обязательного инструмента останавливает pipeline. Готовые пакеты
при повторном запуске пропускаются; LibreOffice на Linux сохраняет проверку библиотек.

В ядро перенесены LibreOffice, Ollama, Tesseract и Chrome for Testing с
chromedriver. Прежние CLI-алиасы и Python-файлы модулей остаются адаптерами.
Службы ОС и доменная логика модулей не переносились. Старые setup-задачи
сохранены: повторная установка готового инструмента ничего не скачивает.

`packages.yaml` продолжает регистрировать специфичные инструменты. Ссылка
на общий инструмент выглядит так:

```yaml
packages:
  libreoffice:
    use: libreoffice
```

Переопределение имени общего инструмента запрещено.

Обновление требует согласованного кода обёртки, `core/api` и модульных адаптеров.
Прежние полные определения LibreOffice, Ollama, Tesseract и Chrome в модульных
`packages.yaml` конфликтуют с новым реестром ядра. Перед первым `setup` они
должны быть заменены ссылками `use`, а старые CLI — адаптерами общих установщиков.
Один коммит ядра без этих изменений модулей не является готовым обновлением
существующей установки.

Повторные явно записанные ключи пакетов и полей YAML отклоняются;
стандартные anchors и переопределения через `<<` поддерживаются.
`huggingface_models.yaml` и `ollama_models.yaml` читаются вместе с новым
манифестом: одинаковые объявления объединяются, противоречащие объявления
одной модели или одной переменной окружения завершаются ошибкой.

## Загрузки и восстановление

В `platforms.<os>` архивного пакета доступны `mirrors: [URL, ...]` и `sha256`
из 64 шестнадцатеричных символов. Для общих custom-установщиков:

```yaml
download:
  mirrors:
    - https://mirror.example.invalid/{name}/{version}/{filename}
  sha256: {}  # имя исходного файла: проверенная SHA256
```

URL здесь — пример, а не действующее зеркало. Кэш проверяется перед
использованием; источники перебираются по очереди. Загрузка идёт в отдельный
временный файл и заменяет кэш после проверки. SHA256 сверяется, если задан.
Для ZIP проверяется CRC, для TAR — структура и конец сжатого потока
(CRC/EOF для gzip, проверка потока XZ), для MSI/tar.zst — сигнатура.
Эти проверки не заменяют проверенную SHA256: старые источники перенесены
без выдуманных хэшей. Отказ источника и неверные хэши покрыты тестами.

Выходящие из каталога пути ZIP и ссылки запрещены; TAR использует фильтр
`data` Python 3.12. Архивные пакеты, LibreOffice, Ollama, Tesseract и Chrome готовятся
в отдельном каталоге; неудачная замена восстанавливает прежнюю версию.
Занятый Windows-службой бинарник может помешать замене: перед явной
переустановкой процесс следует остановить. Tesseract переносит в подготовительный
каталог прежние словари и сопутствующие библиотеки; при отказе загрузки или
копирования рабочий каталог остаётся прежним. Готовность требует бинарника
и двух файлов tessdata.

Предпосылки Linux: `dpkg-deb`, `apt-get download`, `ldd` для LibreOffice,
`zstd` для Ollama. На Windows LibreOffice использует `msiexec`, Tesseract —
бинарник из PATH или 7-Zip. Поддержка произвольного Linux и macOS не заявляется.

Записи реестра поддерживают `minimum_sizes`: относительный путь файла
внутри пакета → положительное целое число байт. Пороги проверяются для marker
и объявленных `required_files` как в установленном каталоге, так и перед заменой.
Для Tesseract заданы пороги, совпадающие с проверками установщика:
1025 байт для бинарника и 1024 байта для каждого основного файла tessdata.
Без объявления порог равен одному байту, что сохраняет прежнюю совместимость.
Минимальный размер не подтверждает подлинность и полную исправность бинарника;
проверка SHA256 применяется отдельно, если хэш объявлен.

## Исправления повторной проверки

После первоначальных 594 тестов добавлены 24 регрессионных теста deployment
и ещё три теста загрузчика Ollama. Итоговые наборы содержат 618 и 16 тестов.
До исправлений отдельно воспроизведены отказ перехода на зеркало при
`IncompleteRead`, принятие gzip без завершающего блока, изменение прежнего
языкового файла при отказе обновления Tesseract и необработанный `TypeError`
при списке/объекте в `provider`.

- Обрывы HTTP теперь обрабатываются как отказ источника. Длина ответа
  проверяется при наличии Content-Length, затем может использоваться зеркало.
- Проверка сжатых TAR дочитывает поток до конца, чтобы обнаружить повреждение
  CRC и усечённый конец. Ошибки ZIP/zlib/XZ переводятся в ошибку проверки файла.
- Query и fragment URL не попадают в имя кэша, что устраняет недопустимые
  имена файлов на Windows для подписанных ссылок.
- Tesseract подготавливает обновление отдельно и заменяет каталог только
  после проверки. Отказы языковых файлов, копирования бинарника и отсутствие
  источника не меняют прежнюю установку. Дополнительные словари и DLL сохраняются.
  Повторная установка из portable PATH не создаёт ссылку бинарника на себя.
- Неверный тип `provider` возвращает контролируемую ошибку манифеста.
- Chrome и Tesseract принимают `--refresh`; проверены передача этого флага
  общим реестром, совместимость `--force --refresh` и обновление языковых файлов.
- Повторный ключ в `packages.yaml` больше не перекрывает первое объявление
  молча. Общий YAML-reader сохраняет вложенные merge/anchor-конструкции.
  Ошибочная кодировка YAML/TOML и неверная структура Python-групп возвращают
  контролируемую ошибку конфигурации.
- Согласованы проверки минимального размера Tesseract в реестре и установщике:
  слишком короткий бинарник не приводит к пропуску восстановления.
- Проверены переменные процесса в обоих загрузчиках моделей. Пустая
  обязательная модель останавливает загрузчик, необязательная пропускается.
  Противоречащие `repo`/`name` отклоняются, одинаковые алиасы нормализуются.
