# core.analytics — первый перенос этапа C

Срез 23.10.2026. В `core/api/src/core/analytics/eda.py` перенесены четыре операции:
сводка колонок, распределения, корреляции и IQR-выбросы. Это первая поставка C;
моделирование, табличный ввод/вывод, агрегации и сходство текстов ещё не перенесены.

## Граница библиотеки

```python
from src.core.analytics.eda import (
    compute_summary,
    compute_distributions,
    compute_correlations,
    compute_outliers,
)
```

Вход — подготовленный `polars.DataFrame`, выход — прежние словари и списки
результатов. Функции не изменяют таблицу. Библиотека не импортирует Django,
Celery, ORM, настройки проекта или код модулей; не читает источники и не запускает
задачи. Импорт самого пакета `src.core.analytics` не загружает Polars/NumPy/ML.

В BI остался `api/eda/engine.py`: именованные импорты операций и прежний
`run_full_eda`. Его тело сохранено, включая состав результата, `meta` и пять
сообщений прогресса. Прежние имена функций и констант доступны в том же месте.
Загрузка и преобразование датасета, выборка EDA, права, Celery и сохранение отчёта
продолжают принадлежать модулю. Старые отчёты не пересчитываются, миграций нет.
Профиль рекомендаций, использующий `compute_summary` через прежний импорт,
также получает вычисление из ядра без изменения своего адаптера.
API с новой библиотекой и адаптер BI поставляются согласованно: перед обновлением
адаптера библиотека уже должна присутствовать. Указатели подмодулей не обновляются.

## Зависимости

Optional-группа `analytics` корневого Poetry содержит `polars = "^1.35.2"` —
прежнее ограничение потребителя. Единый lock фиксирует Polars и polars-runtime-32
1.44.2, совпадающие с проверенным окружением. Все 206 прежних записей сохранили
версии. Ни Torch/CUDA, ни statsmodels/pyarrow, ни другие модульные зависимости
в этой поставке не обновлялись.

Группа добавлена аддитивно. Существующая декларация Polars в BI сохранена:
его `runtime_requirements.yaml` уже входил в незакоммиченный остаток, поэтому
этот файл не редактировался и не включён в серию. Пока группа не объявлена
потребителем, действующий модульный установщик обеспечивает прежнюю зависимость.
Перевод BI на `python.groups: [analytics]` и удаление повторной декларации —
следующая согласованная часть переноса зависимостей. Для потребителей механизм
runtime-групп уже существует в lifecycle A; новый установщик не добавлен.

## Совместимость вычислений

До изменения движка зафиксированы результаты шести таблиц: смешанные числовые,
категориальные и даты; пустая типизированная; полностью NULL; одна строка;
константы; NaN/Infinity. SHA256 исходного движка:
`0554e7afd8838f66841cfc9df7f18a51f87d7283fdf3b8f4391210fe3ff048fd`.
Результаты сохранены в шести JSON-фикстурах тестов ядра. Затем выполнено точное
сравнение старого и нового исполнения на этих таблицах и ещё 100 таблицах
с seed 20261023: все 106 совпали.

Нормализация сравнения касается только пар «категория — количество»:
Polars не обещает порядок категорий с одинаковой частотой. Производственная
сортировка не менялась. Числовые значения, поля, матрицы, порядок колонок,
границы гистограмм и выбросов сравниваются без округляющего допуска.

Сохранены прежние соглашения: выборочное стандартное отклонение, квантиль Polars
по умолчанию, NULL в числе уникальных значений, доля выбросов от всех строк,
20 бинов, 15 категорий и первые 30 числовых полей корреляции. Нечисловые даты
и bool остаются категориями. Исправление старых особенностей алгоритма не
смешано с переносом: в частности, обработка нулевой границы гистограммы через
прежнюю цепочку `or` и классификация Decimal не изменены. Эти соглашения не
являются новой универсальной спецификацией для будущих операций.

## Проверки

Новые тесты сначала подтвердили отсутствие вычислительного модуля ядра и то,
что адаптер ещё не делегировал операции. После переноса:

- 12 тестов ядра и 4 теста адаптера прошли; отдельный discovery ядра тоже прошёл.
- Проверены входная неизменность, все десять прежних числовых типов, даты/bool,
  лимиты, NULL, пустая таблица, статистические соглашения и прогресс отчёта.
- Два свежих процесса проверяют работу без Django/Celery/доменных пакетов
  и отсутствие eager-импорта optional-зависимостей.
- `ergoms poetry check --lock` прошёл с прежними deprecation-предупреждениями.
- Настоящий Poetry dry-run с `--with=analytics` распознал обе зависимости группы
  как уже установленные. Он также показывает существующий drift setuptools
  84.0.0 против 81.0.0 в lock; изменение пакетов не выполнялось.

Полный серверный набор BI: 138 тестов, OK, один SKIP браузерного сценария,
который включается отдельным флагом. Использованы штатные test-настройки,
уникальная `test_ergo_*` PostgreSQL-БД, locmem-кэш и брокер в памяти. Тестовая БД
удалена Django, собственный PostgreSQL-контейнер снова остановлен. ERROR/Traceback
для `secret connection details` и `broker password must not leak` в журнале
принадлежат намеренно смоделированным отказам в тестах источника и публикации задач.

Точный состав будущих коммитов проверен отдельно: из Git-архивов исходных API
`9f3d8fd` и BI `5cc918d` собрана копия с добавлением только 13 наших файлов
кода/тестов/фикстур. Прежние локальные изменения BI не включались; все 16 тестов
этого состава прошли. Отдельная проверка сохранности охватывает 22 репозитория:
все 197 прежних локальных файлов совпали по хэшам. Тело `run_full_eda` дополнительно
сравнено по AST и не изменилось.

Штатный `ergoms core-rules-check` завершился кодом 1 с теми же пятью прежними
ошибками размера документов CRM: campaign-mail, payment-registry, processes,
shared-catalog и BEHAVIOR.md. Изоляция ядра/всех модулей, bridge-контракты,
манифесты, границы данных, отсутствие доменных имён и синтаксис прошли.
Новых нарушений не обнаружено. Чужие документы не исправлялись.

Первоначальные архитектурные процессы в песочнице ожидали локальный socketpair
при импорте Daphne. Стек сохранён; собственные зависшие процессы остановлены.
Повтор с разрешёнными локальными сокетами выполнил штатный валидатор целиком.
Его исходники и механизмы проверки не изменялись. Промежуточный изолированный
QA-launcher до выполнения проверок не дошёл и как успешная проверка не учитывается.

Диагностические попытки сохранены отдельно. `ergoms poetry install --dry-run`
попадает в модульный установщик, который не реализует dry-run: попытка завершилась
на получении setuptools. Проверено, что setuptools остался 84.0.0, Torch —
2.10.0+cu128, остальные проверенные версии не изменились. Настоящая проверка плана
выполнена через `ergoms poetry run poetry install --with=analytics --dry-run --no-root`.
Poetry lock потребовал отдельного кэша внутри проекта: первоначальная ошибка
«нет доступа к PyPI» фактически была отказом записи в кэш Windows-профиля.
Глобальные настройки и код lifecycle не менялись.

Два первоначальных BI-запуска остановились до тестов: параметр `-v` поглощался
PowerShell, затем использован неверный адрес WSL вместо фактического loopback
порта QA PostgreSQL. Исправлялись только игнорируемые QA-скрипты; рабочие
настройки БД и код CLI не менялись.

В этой поставке нет новой приёмки Linux, чистой установки optional-группы или
браузерных сценариев. Проверка плана установки и существующее окружение не
заменяют эти прогоны. Остальные части C не считаются выполненными.
