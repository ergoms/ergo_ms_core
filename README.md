# ERGO MS

Настоящий документ формализует принципы проектирования, развертывания и эксплуатации интеллектуального фреймворка ERGO MS. Система ориентирована на построение и оркестрацию модульных решений любой предметной области, обеспечивая строгую изоляцию ядра и подключаемых доменных компонентов.

## Описание

ERGO MS представляет собой интеллектуальный фреймворк для проектирования и оркестрации модульных программных систем, реализованный на основе архитектурного паттерна «ядро + модули». Фреймворк обеспечивает строгую изоляцию компонентов, унифицированные интерфейсы взаимодействия и декларативную конфигурацию развёртывания.

**Технологический стек:**
- Серверная часть: Django 5.2, Django REST Framework
- Клиентская часть: Vue.js 3, Vite
- Система управления базами данных: PostgreSQL 14+ | SQLite | MySQL
- Обработка асинхронных задач: Celery, Redis
- Управление зависимостями: Poetry (Python), npm (Node.js)

## Быстрый старт

> **⚠️ КРИТИЧНОЕ ТРЕБОВАНИЕ:** Абсолютный путь к корневому каталогу системы должен содержать исключительно символы латинского алфавита (A-Z, a-z), цифры (0-9), дефис (-) и нижнее подчёркивание (_). Использование символов кириллицы, иероглифов или специальных символов в пути файловой системы приведёт к критическим ошибкам инициализации модулей и сбоям в работе инструментов сборки (Vite, Poetry, npm).
> 
> **Корректные примеры путей:**
> - `C:\projects\ergo_ms\`
> - `/var/www/ergo-ms/`
> - `/home/user/projects/ergo_ms_core/`
> 
> **Некорректные примеры путей:**
> - `C:\проекты\ergo_ms\` ❌
> - `/home/пользователь/ergo_ms/` ❌
> - `C:\projects\ergo ms\` ❌ (пробел в пути)

**Этап 1. Требуемые программные зависимости**

Система предполагает наличие следующих компонентов инфраструктуры:
- Python 3.12 ([официальный сайт](https://www.python.org/downloads/))
- Node.js 18+ ([официальный сайт](https://nodejs.org/))
- PostgreSQL 14+ ([официальный сайт](https://www.postgresql.org/download/))
- Git ([официальный сайт](https://git-scm.com/downloads))

**Этап 2. Клонирование репозитория**

```cmd
git clone <repository-url> ergo_ms_core
cd ergo_ms_core
```

**Этап 3. Инициализация конфигурационных файлов**

```cmd
copy .env.example .env
copy databases.yaml.example databases.yaml
```

Полученные конфигурационные дескрипторы `.env` и `databases.yaml` подлежат корректировке в соответствии с параметрами целевой инфраструктуры (детальная спецификация представлена в разделе [Настройка конфигурационных файлов](.docs/configuration.md)).

**Этап 4. Установка зависимостей и инициализация окружения**

При первой установке команда `ergoms` ещё недоступна — она устанавливается в ходе полной настройки. Запускайте полную настройку **напрямую скриптом**:

*Вариант A: интегрированная среда разработки (VS Code/Cursor)*
```
Ctrl+Shift+P → Tasks: Run Task → Setup Full System
```
Задача запускает скрипт setup-full (на шаге 4 устанавливается CLI), затем расширения. После этого команда `ergoms` доступна в терминале.

*Вариант B: командная строка*

**Windows (PowerShell):**
> **⚠️ Первый шаг для Windows:** перед выполнением любых команд PowerShell необходимо установить политику выполнения:
```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

После установки политики выполните (из корня репозитория):
```powershell
.\core\deployment\windows\ergo_ms.ps1 setup-full
```

**Linux (Bash, при необходимости с привилегиями суперпользователя):**
```bash
sudo bash core/deployment/linux/ergo_ms.sh setup-full
```

Скрипт setup-full создаёт venv, ставит Poetry, зависимости, на шаге 4 устанавливает CLI (`ergoms`). После выполнения полной настройки можно использовать `ergoms` для всех дальнейших команд.

> **⚠️ Требование безопасности:** процедура регистрации системных служб требует административных привилегий операционной системы.

**Этап 5. Запуск системы в режиме разработки**

*Рекомендуемый способ (VS Code/Cursor):*
```
Ctrl+Shift+B
```

*Альтернативный способ (CLI):*
```cmd
ergoms start
```

> **ℹ️ Особенность архитектуры:** в режиме разработки Django инициализирует два параллельных процесса: основной обрабатывает HTTP-запросы, вспомогательный осуществляет мониторинг изменений исходного кода и выполняет горячую перезагрузку модулей. Данная конфигурация соответствует штатному режиму функционирования.

**Этап 6. Сетевые точки доступа**

- Клиентское веб-приложение: `http://localhost:8001`
- API-сервер: `http://localhost:8000`
